# Vehicle Groups (Advanced Automate)

The **Vehicle Groups** tab is the core of the WiCAN Pro Automate engine. Unlike the flat lists in the Standard or Custom tabs, Vehicle Groups allow you to build intelligent, hierarchical polling profiles. 

By grouping parameters together, you can apply **conditional logic** (e.g., only poll when the engine is running), assign unique **Group MQTT topics**, and prioritize CAN bus bandwidth using independent polling intervals.

---

## 1. Group-Level Configuration

When you click **"+ Create New Vehicle Group"**, a new group container is generated. You can have multiple groups running simultaneously, each with its own rules.

::img{src="/automate/vehicle_group_init.png" alt="Scanning for PIDs" border}
::

### Group Header Settings
At the top of each group, you define how and when the group operates:

| Setting | Description |
| :--- | :--- |
| **Group Name** | A descriptive label for the group (e.g., `Battery_Cells` or `High_Speed_Dash`). |
| **Period (ms)** | The baseline polling interval for every PID inside this group. |
| **Condition** | The logic determining *when* this group is allowed to poll the CAN bus. |
| **Enabled** | A master toggle to instantly turn the entire group on or off. |
| **Initialization String** | (Optional) Commands sent to the OBD chip *before* this group begins polling (e.g., `ATTP6; ATZ;`). |

### Conditional Execution Options
The **Condition** dropdown is one of the most powerful features. It prevents unnecessary CAN traffic:
* **always:** The group polls continuously as long as the device is awake.
* **voltage:** The group only polls when the vehicle battery voltage is above the set Automate threshold.
* **engine_running:** The group only polls when the WiCAN detects the engine is actively running (RPM > 0).
* **mqtt_on_demand:** The group remains dormant and only executes a polling sweep when explicitly commanded via an incoming MQTT message. *(See Section 6 below for details).*

## 2. Populating a Group

Once your group is created, you need to add PIDs to it. You have two ways to do this:

### Option A: Migrating Flat PIDs (Recommended)
If you already set up parameters in the Standard or Custom tabs, you can automatically migrate them into the Groups system using the buttons at the bottom of the page:
* **Copy Custom PIDs:** Takes everything from the User Custom / Vehicle Specific tabs, groups them by their Init String and Period, and creates new organized groups for them.
* **Copy Standard PIDs:** Takes your enabled Service 01 parameters and puts them into a dedicated "Standard PIDs" group.

> [!NOTE]
> This is a one-way migration. Once converted, you should manage your parameters exclusively within the Vehicle Groups tab.

### Option B: Manual Addition
Click **"+ Add PID Card"** within a group to manually create a new diagnostic request.

## 3. Configuring PID Cards

Inside a group, data is organized into **PID Cards**. A single PID Card represents one request sent to the vehicle (e.g., `010C` for RPM), but it can contain multiple "Extraction Fields" to pull different data out of that single response.

::img{src="/automate/vehicle_group_pid.png" alt="Scanning for PIDs" border}
::


### PID Header
* **PID:** The Hexadecimal command sent to the ECU (e.g., `010C` or `220101`).
* **Description:** A human-readable label for the request.
* **Enable:** Toggle this specific request on or off without deleting it.
* **Clone:** The `[ ]` button duplicates the entire PID card to save time when making similar requests.

### Extraction Fields (Parameters)
For every PID, you must define at least one extraction field to process the vehicle's response:
* **Field Name:** The key name sent in the JSON payload (e.g., `engine_rpm`).
* **OnChg (Send Only on Change):** If checked, the WiCAN will poll the data based on the group's period, but will *only* transmit it to your destination if the value has changed since the last poll. This drastically reduces Wi-Fi and MQTT bandwidth.
* **Expression:** The math formula used to convert the raw Hex response into human-readable numbers. See the following for a list of supported [expressions](/web_interface/automate/expressions/). 

**Special Expression Types:**
Instead of standard math formulas (like `A*2`), you can use two built-in special expressions for advanced data handling:
* `RAW`: This bypasses math evaluation and combines multiple multi-frame CAN responses into one continuous, long hex string. This is extremely useful for large blocks of repeating data (like battery cell voltages). You can then send this `RAW` hex string to Home Assistant and use HA's powerful template engine to decode the payload off-device.
* `DTC_RAW`: This triggers specialized internal processing designed specifically for parsing and formatting Diagnostic Trouble Codes (DTCs) from the ECU.

## 4. Advanced Routing: The `MQTT_Grp` Destination

While you can route any individual extraction field to a specific Topic/Dest, Vehicle Groups introduce a unified routing method:

1. **Set the Group MQTT Topic:** In the Group Header, define a master topic (e.g., `vehicle/tesla/battery`).
2. **Set Field Destination:** Inside your PID's Extraction Field, change the Destination Type dropdown to **`MQTT_Grp`**.
3. **The Result:** All fields within that group set to `MQTT_Grp` will be bundled and published to that single master topic, keeping your broker clean and organized.

## 5. UI Tools: Drag-and-Drop & Testing

### Drag-and-Drop Reordering
The Automate engine processes groups and PIDs in top-down order.
* **Reorder Groups:** Click and hold the `☰` icon in the Group Header to drag the entire group up or down the list.
::img{src="/automate/vehicle_group_pid.png" alt="Scanning for PIDs" border}
::
* **Move PIDs:** Click and hold the `☰` icon on a PID Card to drag it up or down, or even drag it out of its current group and drop it into a different group. This is incredibly useful if you want to quickly change a PID's polling frequency—just drag it from a `1000ms` group and drop it into a `5000ms` group.

> [!WARNING]
> Be careful when moving PIDs between groups! If a group relies on a specific **Initialization String** to talk to a specific ECU/module address, dropping a PID meant for a different module into that group will cause the request to fail.

### The Live Testing Console
Before saving your configuration, you can test a group live against your vehicle:
1. Click the green **Play (►)** button in the Group Header.
2. A terminal window will appear at the bottom of the group.
3. The WiCAN will execute the Initialization String, poll every enabled PID in the group, and display the Raw Hex response alongside your calculated math results. 

::img{src="/automate/vehicle_group_test.png" alt="Scanning for PIDs" border}
::

## 6. How `mqtt_on_demand` Works

If you set a group's condition to **`mqtt_on_demand`**, the WiCAN Pro will load the group into memory but will *never* poll it automatically. It sits idle, saving maximum CAN bandwidth, until you explicitly tell it to run via MQTT.

This is perfect for heavy, multi-frame data requests that you only need occasionally, such as:
* Querying the vehicle's VIN.
* Pulling a massive list of battery cell voltages only when a charging session begins.
* Requesting full diagnostic trouble codes (DTCs) via a button on your dashboard.

### Triggering via Home Assistant
To trigger an on-demand group, your home automation system must publish a specific JSON payload to the WiCAN's RX command topic. 

### Understanding the Configuration
* **`group_name`:** This must exactly match the name of the group as defined in your WiCAN Vehicle Groups tab.
* **`timeout`:** Defined in seconds. In the example above, the WiCAN will poll the group for 120 seconds and then stop. If you set `"timeout": 0`, the group will poll continuously until you send the `payload_off` command.
* **`command_topic` / `state_topic`:** You must replace `9c139e8f55e5` with your WiCAN's specific device address...

Here is an example of a Home Assistant Switch that turns a group named "PCM STD" on for 120 seconds, and then automatically turns it off.

```yaml
    - name: "Fusion Toggle STD PCM Group"
      unique_id: "fusion_toggle_std_pcm_group"
      default_entity_id: "switch.fusion_toggle_std_pcm_group"        
      state_topic: "wican/9c139eXXXXXX/cmd"
      command_topic: "wican/9c139eXXXXXX/cmd"
      payload_on: '{"command": "set_group", "group_name": "PCM STD", "active": true, "timeout": 120}'
      payload_off: '{"command": "set_group", "group_name": "PCM STD", "active": false}'
      state_on: "ON"
      state_off: "OFF"
      optimistic: true
```
